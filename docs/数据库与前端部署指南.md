# RAG-AI 数据库与前端部署实战指南

> 本指南面向需要把 RAG-AI 全栈落地到企业或公共环境的工程团队，涵盖向量数据库（Qdrant / Milvus）部署、前端（Next.js / Streamlit）上线与运维要点。

---

## 1. 部署矩阵概览

| 组件                | 推荐部署方式             | 目标环境                |
|---------------------|--------------------------|-------------------------|
| Qdrant（默认向量库）| Docker Compose / K8s     | 单机 / 小型集群         |
| Milvus（大规模）    | Helm + Kubernetes        | 亿级向量、企业生产环境   |
| FastAPI 后端        | Docker Compose / K8s     | 同上                     |
| Next.js 前端        | Vercel / Docker / K8s    | 面向公众访问             |
| Streamlit 控制台    | Docker / K8s             | 内部运营、调试           |
| 监控栈              | Prometheus + Grafana     | 性能与健康度监控         |

部署前，请准备：

- `.env` 文件：通过 `python setup.py` 或手动复制 `.env.example` 并填写。
- TLS/域名：如需对外服务，准备证书、域名解析。
- 存储：持久化挂载点（NFS、云盘或对象存储）。

## 2. 向量数据库部署

### 2.1 Qdrant（默认）

#### 2.1.1 本地 / 单机 Docker

```bash
mkdir -p /data/qdrant_storage

docker run -d --name rag-qdrant \
  -p 6333:6333 -p 6334:6334 \
  -v /data/qdrant_storage:/qdrant/storage \
  qdrant/qdrant:v1.7.3
```

- HTTP API: `http://<host>:6333`
- gRPC: `http://<host>:6334`
- 在 `.env` 中设置：

```dotenv
VECTOR_DB_BACKEND=qdrant
QDRANT_HOST=<host>
QDRANT_PORT=6333
COLLECTION_NAME=ai_papers
```

#### 2.1.2 Docker Compose（与后端同部署）

`docker-compose.yml` 已提供服务模板，可在 `services` 中启用：

```yaml
services:
  qdrant:
    image: qdrant/qdrant:v1.7.3
    ports:
      - "6333:6333"
    volumes:
      - ./qdrant:/qdrant/storage
```

与 FastAPI、Redis、Nginx 一同启动：

```bash
docker-compose up -d qdrant api nginx
```

#### 2.1.3 Kubernetes

使用 Helm：

```bash
helm repo add qdrant https://qdrant.github.io/qdrant-helm
helm install rag-qdrant qdrant/qdrant \
  --set service.type=LoadBalancer \
  --set persistence.storageClass=fast-disks \
  --set persistence.size=200Gi
```

在 `.env` 中填入 LoadBalancer 地址即可。

#### 2.1.4 调优建议

- `config.json` 覆盖 HNSW 参数：`m`=32、`ef_construct`=400，可提升召回。
- 热数据可使用 Qdrant 的 `payload_index`；常用字段：`authors`, `year`, `concepts`。
- 大量写入时，将 `snapshots` 放到对象存储，用于容灾和回滚。

---

### 2.2 Milvus（大规模场景）

#### 2.2.1 准备依赖

- Kubernetes 集群（≥ 3 节点，至少 16C+64G）。
- 对象存储（MinIO / S3）用于向量文件持久化。
- `pymilvus` 已列入 `requirements.txt`，确保安装。

#### 2.2.2 部署 Helm

```bash
helm repo add milvus https://milvus-io.github.io/milvus-helm/
helm install rag-milvus milvus/milvus \
  --set cluster.enabled=true \
  --set etcd.persistence.size=50Gi \
  --set minio.persistence.size=200Gi \
  --set dataNode.resources.requests.memory=4Gi
```

#### 2.2.3 RAG-AI 配置

`.env` 关键字段：

```dotenv
VECTOR_DB_BACKEND=milvus
MILVUS_URI=http://rag-milvus-milvus-proxy.milvus.svc.cluster.local:19530
MILVUS_COLLECTION=ai_papers
MILVUS_USERNAME=""
MILVUS_PASSWORD=""
MILVUS_DB_NAME=default
MILVUS_DIM=1024
```

如启用鉴权，在 Helm `values` 中设置账号，并同步写入 `.env`。

#### 2.2.4 索引策略

| 数据规模        | 索引类型           | 参数建议                                    |
|-----------------|--------------------|---------------------------------------------|
| ≤1 亿向量       | HNSW               | `M=48, efConstruction=512`                  |
| 1–5 亿向量      | IVF_FLAT / IVF_PQ  | `nlist=4096`, `nprobe=32`；PQ 可引入压缩      |
| ≥10 亿向量      | HNSW+分区 / DiskANN | 结合维度降采样，并开启负载均衡和分片          |

定期执行 `compact` 及 `flush`，减少碎片。

## 3. 后端部署（FastAPI）

### 3.1 Docker Compose

`docker-compose.yml` 中 `api` 服务示例：

```bash
docker-compose up -d api
```

或包含依赖一起启动：

```bash
docker-compose up -d qdrant redis api nginx
```

- API 默认端口：`8000`，可在 Compose 中映射至 80/443。
- 若运行在 Kubernetes，可配合 Ingress/Nginx Controller 暴露。

### 3.2 生产优化

- 使用 `uvicorn api.enhanced_main:app --workers 4 --host 0.0.0.0 --port 8000`。
- 设置 `ENABLE_CONTEXTUAL_COMPRESSION`、`USE_SMART_RERANKING`，提升响应质量。
- 根据并发情况在 `.env` 中扩大 `MAX_PAPERS_PER_FETCH` 或限制 `days_back`。
- 结合 Redis/Multi-layer Cache，减少重复调用。

### 3.3 日志与监控

- FastAPI 日志默认写入 `storage/logs`。
- `monitoring` 目录提供 Prometheus 配置，可配合 Grafana 展示 `rag_ai_*` metrics。

## 4. 前端部署方案

### 4.1 Next.js 前端

项目位于 `frontend/`，默认使用 App Router。

#### 4.1.1 本地开发

```bash
cd frontend
npm install
npm run dev    # http://localhost:3000
```

确保 `.env` 中的后端地址或在 `frontend/.env.local` 设置：

```dotenv
NEXT_PUBLIC_API_HOST=http://localhost:8000
```

#### 4.1.2 生产构建

```bash
npm run build
npm run start  # 默认监听 3000 端口
```

#### 4.1.3 Docker 部署

`Dockerfile.frontend` 示例：

```bash
docker build -f Dockerfile.frontend -t rag-frontend .
docker run -d -p 3000:3000 rag-frontend
```

若需要绑定域名/TLS，可放在 Nginx 后面：

```nginx
server {
  listen 80;
  server_name rag.example.com;

  location / {
    proxy_pass http://frontend:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
  }
}
```

#### 4.1.4 Vercel / Static Hosting

1. 在 Vercel 上导入 Git 仓库。
2. 配置环境变量 `NEXT_PUBLIC_API_HOST=https://api.example.com`。
3. 部署完成后，可开启 Edge 缓存、图像优化等功能，提高全局访问速度。

### 4.2 Streamlit 控制台

`enhanced_app.py` 提供运营面板：

```bash
streamlit run enhanced_app.py --server.port 8501 --server.address 0.0.0.0
```

Docker 方式：

```bash
docker build -f Dockerfile.frontend -t rag-streamlit --target streamlit .
docker run -d -p 8501:8501 rag-streamlit
```

可作为内部工具监控检索链路、用户画像、缓存命中情况。

## 5. 端到端上线案例（Docker Compose）

示例目录结构：

```
rag-ai/
├── docker-compose.yml
├── .env
├── qdrant/
├── scripts/
└── frontend/
```

`docker-compose.yml` 核心片段：

```yaml
services:
  api:
    build: .
    command: uvicorn api.enhanced_main:app --host 0.0.0.0 --port 8000 --workers 4
    env_file: .env
    depends_on:
      - qdrant

  frontend:
    build:
      context: .
      dockerfile: Dockerfile.frontend
    environment:
      NEXT_PUBLIC_API_HOST: http://api:8000
    depends_on:
      - api

  qdrant:
    image: qdrant/qdrant:v1.7.3
    volumes:
      - ./qdrant:/qdrant/storage

  nginx:
    image: nginx:1.25
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
    ports:
      - "80:80"
      - "443:443"
    depends_on:
      - frontend
```

启动：

```bash
docker-compose up -d
```

访问：

- 前端：`http://localhost`
- API 文档：`http://localhost/docs`

## 6. 运维与故障排查

| 场景                           | 建议处理方式 |
|--------------------------------|--------------|
| 数据采集失败（OpenAlex）      | 检查网络、降低并发（`max_pages`）、使用 `scripts/smoke_test_sources.py` 验证 |
| Semantic Scholar 频繁限流      | 配置 API Key、添加重试与退避策略、遵守速率限制 |
| 向量库响应慢                   | 优化 HNSW/IVF 参数、增加实例、副本/分片、控制向量维度 |
| Next.js 构建失败               | 确认 Node 版本（推荐 ≥18）、清除 `node_modules` 重装依赖 |
| 前后端跨域                     | 使用 Nginx 设置 `proxy_set_header`, FastAPI 启用 `CORSMiddleware` |
| 日志过大                       | 使用 Logrotate 或容器内 `max-size` 限制 |
