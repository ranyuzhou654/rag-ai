# RAG-AI 中文使用教程（最新版）

> 面向希望快速搭建「基于检索增强生成 (RAG) 的学术论文问答/推荐系统」的工程团队，本文总结了最新代码改动后的完整流程：环境配置、数据采集、向量索引、问答链路与运维要点。

## 1. 系统概览

- **数据源**：ArXiv、OpenAlex、Hugging Face Papers、主流 AI 博客，支持每日增量更新与长期历史回溯。
- **元数据优先策略**：先写入标题/摘要/关键词等轻量信息，按需再下载全文，降低存储压力并符合版权约束。
- **语义增强**：自动引用 Semantic Scholar TLDR 与概念标签；在检索、重排序、上下文构建阶段都会利用这些元数据。
- **向量数据库**：默认 Qdrant，可平滑迁移到 Milvus；支持混合检索（向量 + BM25 + 概念匹配）。
- **链路优化**：Cross-Encoder 精排、智能上下文压缩、多表示索引与多层缓存，保证回答质量与延迟。

## 2. 环境与配置

### 2.1 快速脚本

针对云主机或新环境，可运行 `python setup.py`：

1. 自动检测数据盘、创建目录 `rag_zh_project_data`、`models`、`data`、`logs`。
2. 生成与仓库模板一致的 `.env`（包含 Semantic Scholar 开关、向量数据库、RAG 模式等）。
3. 可选输入 Hugging Face Token，用于访问受限模型。

### 2.2 `.env` 关键字段

```dotenv
# 存储与模型缓存
STORAGE_ROOT=/opt/rag_zh_project_data
HF_HOME=/opt/rag_zh_project_data/models
TRANSFORMERS_CACHE=/opt/rag_zh_project_data/models

# Hugging Face 认证
HUGGING_FACE_TOKEN=your_token

# 向量数据库
VECTOR_DB_BACKEND=qdrant      # 或 milvus
QDRANT_HOST=localhost
QDRANT_PORT=6333
COLLECTION_NAME=ai_papers

# Semantic Scholar 增强
ENABLE_SEMANTIC_SCHOLAR=true
SEMANTIC_SCHOLAR_API_KEY=     # 可选，提高请求配额

# 多表示索引与上下文优化
ENABLE_MULTI_REPRESENTATION=true
ENABLE_CONTEXTUAL_COMPRESSION=true
USE_SMART_RERANKING=true

# 其他 RAG Feature Toggles
ENABLE_QUERY_INTELLIGENCE=true
ENABLE_AGENTIC_RAG=true
ENABLE_KNOWLEDGE_GRAPH=true
ENABLE_TIERED_GENERATION=true
ENABLE_FEEDBACK_COLLECTION=true

# 高级配置
DEFAULT_RAG_MODE=ultimate
STORAGE_CONTENT_MODE=full     # summary / title_abstract 可压缩存储
```

配置完成后，可执行 `source .env` 或使用 `python-dotenv` 自动加载。

## 3. 数据采集与增量更新

### 3.1 多源采集

运行 `python run_rag_system.py` 即可触发全流程：

- **最近数据**：`python run_rag_system.py --days-back 30 --max-papers 500`
- **历史数据**：`python run_rag_system.py --years 10 --arxiv-categories "cat:cs.AI OR cat:cs.CL OR cat:cs.LG"`
- **只写入元数据**：`python run_rag_system.py --metadata-only`

核心改进：

- OpenAlex 接入，抓取最新论文的概念标签、作者、出版信息。
- Semantic Scholar Graph API 自动补充 TLDR、完善摘要、对缺失作者信息纠偏。
- 元数据写入 `storage/data/raw/metadata_index.json`，后续检索会直接读取。

### 3.2 快速验收（Smoke Test）

配置好网络后建议执行：

```bash
python scripts/smoke_test_sources.py
```

脚本将采集过去一天的数据，统计各数据源数量，并展示首条成功补全 TLDR 的论文，验证 OpenAlex 与 Semantic Scholar 是否连通。

### 3.3 按需下载全文

对于命中率较高的论文，可调用：

```python
from pathlib import Path
from src.data_ingestion.multi_source_collector import MultiSourceCollector

collector = MultiSourceCollector(Path("storage/data/raw"), metadata_only=True)
full_text = await collector.fetch_full_text_on_demand("arxiv_2301.12345")
```

若本地存在缓存，会直接读取；否则下载 PDF → 提取文本 → 更新 metadata 标记。

### 3.4 每日增量

部署定时任务（crontab / Airflow）调用：

```python
await collector.daily_incremental_update()
```

脚本会拉取过去 24 小时的新论文，对比 `processed_ids` 避免重复，并更新本地索引。

## 4. 数据处理与向量索引

### 4.1 文本切分与多表示

- `HierarchicalTextSplitter` 保留章节结构。
- `SemanticGraphSplitter` 根据句向量相似度划分主题块。
- `MultiRepresentationIndexer` 为每个 chunk 额外生成摘要、假设问答等 representation。

配置示例（`configs/config.py`）：

```python
ENABLE_MULTI_REPRESENTATION = True
CHUNK_SIZE = 512
CHUNK_OVERLAP = 50
EMBEDDING_MODEL = "BAAI/bge-m3"
```

### 4.2 Qdrant / Milvus 入库

- 默认 Qdrant：适合单机或轻量级集群。
- 切换 Milvus：修改 `.env` 中的 `VECTOR_DB_BACKEND`，并安装 `pymilvus`。
- 采用 `hybrid_search`：向量分数 + 关键词 BM25 + 概念重叠。

存储策略：

| STORAGE_CONTENT_MODE | 行为                                   | 建议使用场景                 |
|----------------------|----------------------------------------|------------------------------|
| `full`（默认）       | 原文 chunk 全量写入                    | 中小规模语料、需要追溯全文   |
| `summary`            | 写入 LLM 压缩摘要，原文存 metadata 预览 | 中大型语料，节省向量存储     |
| `title_abstract`     | 写入标题 + 摘要/前 200 字              | 超大规模语料，仅需元数据检索 |

## 5. 检索链路改进

1. **向量召回**：`VectorDatabaseManager.search` 会自动融合向量分数、关键词匹配以及概念覆盖度（Semantic Scholar 提供的标签会作为加权项）。
2. **交叉编码器重排**：`AdvancedReranker` 将 TLDR、概念词、标题一起拼接后送入 Cross-Encoder，以提升语义匹配精度。
3. **上下文构建**：`EnhancedContextOptimizer` 在压缩前会插入 TLDR 与概念摘要，辅助 LLM 更快对齐主题。
4. **问答生成**：`UltimateRAGSystem` 结合智能体 RAG、上下文压缩、Tiered Generation，保证大模型响应速度与准确度。

## 6. 推荐与个性化

- `UserProfiler` 追踪用户查询、阅读、反馈行为。
- `RecommendationEngine` 使用概念标签和向量相似度生成每日主题摘要，并可结合 Semantic Scholar TLDR 快速对比最新论文。
- 可在 Streamlit/Next.js 前端展示「今日热点主题 + 推荐论文」列表。

## 7. 监控与运维

- `MetricsCollector` 暴露 Prometheus 指标：检索耗时、缓存命中、向量库操作延迟等。
- 建议在 Docker/Kubernetes 中部署 Qdrant/Milvus + Redis，并配合 Nginx 做负载均衡。
- 通过 `.env` 开启 `ENABLE_FEEDBACK_COLLECTION`，收集用户评分，进一步训练 reranker 或 LLM。
- 若需扩展到多机集群，可将存储根目录挂载到共享文件系统（NFS、S3-Fuse 等），并使用 Helm chart 部署后端服务。

## 8. 常见问题与排查

| 问题                         | 解决方案 |
|------------------------------|----------|
| Semantic Scholar 请求失败   | 检查 `ENABLE_SEMANTIC_SCHOLAR`、API Key；确认网络出口允许访问 api.semanticscholar.org |
| OpenAlex 超时/限流          | 减少并发、增加 `--days-back`、合理设置 `max_pages`，或使用 OpenAlex 提供的快照数据 |
| 检索结果缺乏上下文          | 确认多表示索引开启、`STORAGE_CONTENT_MODE` 没被强行改成 `title_abstract` |
| Qdrant 查询变慢             | 优化 HNSW 参数，或压缩向量维度；查看内存是否足够 |
| Milvus 断连/认证失败        | 核对 `MILVUS_URI`，确认用户密码、TLS 设置；必要时查看 Milvus server 日志 |
