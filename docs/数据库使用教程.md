# RAG-AI 向量数据库使用教程

> 面向需要管理大规模论文/技术文档语料的工程师，详细说明如何选择、部署并维护 RAG-AI 的向量数据库层。

## 1. 总览

- 默认内置 **Qdrant**，适合单机或小规模集群；支持混合检索（向量 + BM25）。
- 当数据量级达到数亿条向量，可切换到 **Milvus** 等分布式方案。
- 通过配置文件 `.env` / `configs/config.py` 控制数据库类型和连接参数。

关键配置（可在 `.env` 中追加）：

```dotenv
VECTOR_DB_BACKEND=qdrant      # 备选：milvus
QDRANT_HOST=localhost
QDRANT_PORT=6333

MILVUS_URI=http://milvus:19530
MILVUS_COLLECTION=ai_papers
MILVUS_USERNAME=
MILVUS_PASSWORD=
```

## 2. Qdrant 使用指南

### 2.1 启动服务

```bash
docker run -p 6333:6333 -p 6334:6334 \
  -v $(pwd)/qdrant_storage:/qdrant/storage \
  qdrant/qdrant:latest
```

- `6333`：HTTP API；`6334`：gRPC。
- 将存储目录挂载到本地，避免容器销毁导致数据丢失。

### 2.2 配置连接

在 `.env` 或部署环境变量中设定：

```dotenv
VECTOR_DB_BACKEND=qdrant
QDRANT_HOST=127.0.0.1
QDRANT_PORT=6333
COLLECTION_NAME=ai_papers
```

项目启动后会自动检查集合是否存在，若不存在则创建并建立必要索引。

### 2.3 性能调优

- 调整 `HnswConfig` 中的 `m`、`ef_construct` 提升召回。
- 使用 `payload_index` 为常用过滤字段建立索引（作者、年份、标签等）。
- 如果查询量大，可通过 docker-compose 或 Kubernetes 部署多实例并做负载均衡。

## 3. Milvus 使用指南

当语料 > 5 亿向量或需要更强的水平扩展能力，推荐部署 Milvus。

### 3.1 部署

方式一：官方 docker-compose（单机混合模式）

```bash
git clone https://github.com/milvus-io/milvus-helm.git
cd milvus-helm/charts/milvus
docker compose up -d
```

方式二：Kubernetes + Helm（生产环境推荐）：

```bash
helm repo add milvus https://milvus-io.github.io/milvus-helm/
helm install my-milvus milvus/milvus --set cluster.enabled=true
```

### 3.2 RAG-AI 配置

在 `.env` 中启用 Milvus：

```dotenv
VECTOR_DB_BACKEND=milvus
MILVUS_URI=http://milvus-standalone:19530
MILVUS_COLLECTION=ai_papers
MILVUS_USERNAME=root
MILVUS_PASSWORD=mypass
```

> 说明：仓库已内置 Milvus 支持，确保安装 `pymilvus` 并在 `.env` 中正确配置即可。

### 3.3 调优建议

- 根据数据维度与规模选择合适的 `index_type`（HNSW、IVF_FLAT、IVF_PQ 等）。
- 通过负载均衡与 Segment 并行提升查询吞吐。
- 使用 MinIO/S3 作为对象存储，配合冷热数据分层。

## 4. 数据存储策略

为平衡检索质量与存储量，可通过 `STORAGE_CONTENT_MODE` 控制写入向量库的文档内容。

| 模式             | 描述                                   | 适用场景             |
|------------------|----------------------------------------|----------------------|
| `full` (默认)    | 保存 chunk 全部文本                     | 语料量较小或需要追溯全文 |
| `summary`        | 保存压缩后的摘要文本，原文存 metadata 预览 | 中大型语料，减少存储 |
| `title_abstract` | 保存标题 + 摘要/前 200 字              | 超大语料，仅需元数据检索 |

设置方式：

```dotenv
STORAGE_CONTENT_MODE=summary
```

## 5. 数据导入流程

1. 准备原始文档（PDF/Markdown/文本）。
2. 执行处理脚本：
   - 最近数据：`python run_rag_system.py --max-papers 500 --days-back 30`
   - 历史数据：`python run_rag_system.py --years 10 --arxiv-categories "cat:cs.AI OR cat:cs.CL OR cat:cs.LG" --arxiv-batch-days 30 --max-results-per-interval 200`
   - 指定仅保存元数据：`python run_rag_system.py --years 10 --metadata-only`
   程序会根据环境变量自动写入 Qdrant 或 Milvus。
3. 若 `ENABLE_MULTI_REPRESENTATION=true`，同一 chunk 会生成摘要、假设问题及对应向量。
4. 构建完成后可使用 `VectorDatabaseManager.get_comprehensive_stats()` 查看统计信息。

## 6. 检索与监控

- 使用 `VectorDatabaseManager.search(...)` 统一调用混合检索。
- 监控指标：
  - 检索耗时、缓存命中率（Prometheus + Grafana 仪表板）。
  - 向量库内部指标（Qdrant Console、Milvus Insight）。

## 7. 故障排查

| 问题             | 排查步骤 |
|------------------|----------|
| 向量库连接失败   | 检查主机/端口、防火墙；确认 `.env` 配置；验证 Docker 容器是否运行 |
| 检索速度慢       | 确认是否开启索引；调高 `ef_search`；降维或使用 ANN 参数调优 |
| 库容量不足       | 改用 `summary` 或 `title_abstract` 模式；启用冷存储；考虑 Milvus 分布式 |
| 数据重复写入     | 导入前运行去重脚本，基于 DOI 或标题哈希检查 |

## 8. 迁移流程

1. 导出原 Qdrant 向量（`/collections/<name>/points`）。
2. 使用官方工具或脚本转换为 Milvus 支持的格式。
3. 重建索引并验证召回结果。
4. 更新 `.env`，重新部署 RAG-AI 指向新向量库。

---

按照以上步骤即可在大规模论文场景下稳定运行 RAG-AI，并根据业务需求灵活切换数据库与存储策略。
